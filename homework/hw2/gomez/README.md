## Reproduce

Python 3.13 or later and the standard library suffice for Parts A and B. From this folder:

```bash
# Use `python3` on Linux/macOS, or `python` on Windows
python3 attack\run.py
python3 defend\run.py
```

Part C used Semgrep 1.182.1 in `.venv` and an already installed local Ollama
0.40.11 `qwen2.5:3b` model. To rerun it from scratch:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install semgrep
ollama list
python3 duel/run.py
```
On Windows use: .venv\Scripts\activate

*(**Note**: You can also use python3 duel/run.py --rescore to bypass the local LLM execution and instantly recalculate metrics using our cached JSON/TXT outputs).*

The run script forces two uncached inferences with fixed, different seeds and keeps the exact prompt, raw model output, raw Semgrep JSON, finding CSV and metric CSV. `.venv` and model cache files are excluded from Git by `.gitignore`.

## Important target distinction

The distributed `vuln-web` source does **not** implement a Medium filter. Our `lab.py` supplies an explicitly documented, deliberately narrow Medium layer before the copied handlers: whitespace-delimited `OR` for SQLi, lowercase `<script` for XSS, and `;` for cmdi. All Part-A bypasses cross this layer and reach the copied vulnerable functions. This is our test configuration for local reproducibility. While the course's teaching copy simulates command construction safely without executing a live shell, the mechanics of these filter bypasses were also empirically cross-verified against a live DVWA Medium instance running in Docker.
